# Pre-authorization

A pre-authorization asks the insurer to **approve a service before you provide
it**. Use it for anything that needs sign-off first: operations, expensive
items, optical, dental, inpatient stays.

## What you do

1. Build the request from the patient's visit — the diagnosis, the items, and
   the supporting information.
2. Send it.
3. Read the decision.

## The decision

| Result | What it means |
|---|---|
| **Approved** | The insurer approved everything. You get an approval number. |
| **Partially Approved** | Some items approved, others reduced or refused. The detail shows which. |
| **Rejected** | The request was refused. The reason is shown. |

## Reading the result

Open the record's **Communication** screen. The **Items** tab shows each line's
approved-versus-requested amount and quantity and its approval number. The
**Inspect** button shows the full request and reply in plain view.

## After approval

Once a pre-authorization is approved you can turn it into a bill and a claim in
a couple of clicks — see [Claims](claims.md).

## Resubmission and follow-ups

- If a request is rejected, you can fix it and **resubmit**.
- A **follow-up** request can be linked to the earlier one so the insurer sees
  the history.

!!! warning "Get the basics right"
    Most refusals come from a missing detail — the treating doctor's license
    number, a required piece of supporting information, or an item code the
    insurer doesn't recognise. The [check before sending](../features.md#the-check-before-sending)
    catches most of these before they leave.
